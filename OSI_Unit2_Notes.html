OSI Model — Overview & Architecture

OSI (Open Systems Interconnection) is a conceptual reference model developed by ISO (International Organization for Standardization) in 1984. It describes how information moves from a software application on one computer through a physical medium to a software application on another computer.

Why it was created

  • Before OSI, different vendors used proprietary, incompatible protocols.
  • OSI gave a universal framework so any two systems could communicate.
  • It splits the complex communication problem into 7 smaller, manageable layers.
  • Each layer is self-contained — it can be updated or replaced without disturbing others.

Peer-to-Peer Processes & Interfaces

Each layer on one device communicates logically with its counterpart (peer) on the other device. This is called peer-to-peer communication.

Key Concepts

  • Peer-to-peer: Transport on Device A ↔ Transport on Device B (logically). Each layer only directly communicates with the layers immediately above and below it in the same device.
  • Upward communication: A layer sends data to the layer above it.
  • Downward communication: A layer receives data from the layer above it and passes it down.
  • Service Access Points (SAPs): The interface between adjacent layers. Each layer provides services via SAPs to the layer above it.
EXAM TIP
Physical layer is the only layer where actual bits travel over the physical medium. All other layers communicate logically (through headers/trailers) rather than directly.

Interface Between Layers

  • Each layer provides services to the layer above it.
  • Each layer uses services of the layer below it.
  • The interface defines what services are offered and how they are accessed — not how they are implemented.
  • This modularity means a layer can be upgraded without changing other layers, as long as the interface is preserved.

Encapsulation & Decapsulation

As data travels down through layers on the sender side, each layer adds its own header (and sometimes trailer). This process is called Encapsulation.
On the receiver side, as data travels up, each layer removes its own header — this is called Decapsulation.

Characteristics of the OSI Model

1. Layered Architecture
7 distinct layers, each with specific function. Communicates only with peer and adjacent layers.
2. Standardized Protocols
Vendor-neutral framework. Devices from different manufacturers can interoperate.
3. Encapsulation / Decapsulation
Headers added going down (sender); headers removed going up (receiver).
4. Modularity
Each layer is independent. Upgrading a protocol in one layer doesn't affect others if interfaces stay the same.
5. Peer-to-Peer Communication
Each layer logically communicates with its counterpart layer on the remote device using headers.
6. Service-Oriented
Each layer provides services upward and consumes services from below. Network layer → routing for Transport layer.
7. Protocol Independence
OSI defines functions, not specific protocols. E.g., at Layer 4 you can use TCP or UDP.
8. Troubleshooting Aid
Issues can be isolated to a specific layer. IP addressing problem? Check Layer 3. MAC issue? Check Layer 2.
9. Interoperability
Different hardware/software systems communicate regardless of underlying architecture.
10. Conceptual, Not Implementation
OSI is a reference model — used for teaching, design, and troubleshooting. TCP/IP is the real-world implementation.

L1 Physical Layer

The lowest layer of the OSI model. Deals with the raw transmission of individual bits from one node to another over a physical medium. It is implemented in both hardware and software but is primarily a hardware layer.

FIG 3 · PHYSICAL LAYER — BIT TRANSMISSION

Core Functions

Line Configuration
Defines how two or more devices are physically connected (point-to-point or multipoint).
Data Transmission Mode
Simplex (one-way), Half-Duplex (two-way, not simultaneous), Full-Duplex (simultaneous two-way).
Topology
Defines physical arrangement of devices — Bus, Star, Ring, Mesh, Hybrid.
Signals & Bit Rate
Determines signal type (digital/analog) and maintains data bit rate quality.
Specification
Specifies mechanical, electrical, and procedural network interface specs.
Bit Conversion
Converts Data Link frames into 1s and 0s for transmission and back on receipt.

Characteristics

SIGNALS

  • Digital Signals: Discrete pulses representing 0s and 1s directly.
  • Analog Signals: Continuous waveform representation of data (used in older telephone lines).

TRANSMISSION MEDIUM

  • Wired: Fiber optic (highest speed, immune to EMI), Coaxial cable, Twisted pair (UTP/STP).
  • Wireless: Wi-Fi (802.11), Bluetooth, cellular (4G/5G), infrared.

DATA FLOW FACTORS

  • Error Rate: Probability of receiving incorrect bits due to noise.
  • Encoding: Method used to represent bits as signals (NRZ, Manchester, etc.).
  • Bandwidth: Maximum data transmission rate of the channel (measured in bps).

TYPES OF NOISE

  • Dispersion: Signal spreads and overlaps in time — corrupts data.
  • Attenuation: Signal weakens progressively over distance.
  • Data Delay (Latency): Transmitted data arrives outside the expected time frame.
EXAM POINT
Physical layer does NOT deal with error correction — that is Data Link's job. Physical layer only transmits bits; it cannot interpret them.

L2 Data Link Layer

Responsible for error-free transfer of data frames between adjacent nodes. Provides reliable, efficient communication and uniquely identifies each device on a local network using MAC addresses.

FIG 4 · DATA LINK SUBLAYERS — LLC & MAC

Two Sub-layers

LLC (Logical Link Control)

  • Transfers packets to the Network layer of the receiver
  • Identifies the network layer protocol from the header
  • Provides flow control
  • IEEE 802.2 standard
  • Acts as the upper part of DLL

MAC (Media Access Control)

  • Link between LLC and Physical layer
  • Used for transferring packets over the network
  • Controls access to shared media (CSMA/CD)
  • Each NIC has a unique 48-bit MAC address
  • Format: AA:BB:CC:DD:EE:FF

Functions of Data Link Layer

FRAMING

Translates raw bit stream from Physical layer into frames. Adds header (containing source & destination MAC) and trailer (containing CRC) to the packet.

FIG 5 · ETHERNET FRAME STRUCTURE

PHYSICAL ADDRESSING

Adds header with destination MAC address. The frame is transmitted to the destination device identified by this hardware address.

FLOW CONTROL

Maintains constant data rate on both sides. Prevents a fast sender (server) from overwhelming a slow receiver. Techniques: Stop-and-Wait, Sliding Window.

ERROR CONTROL

Adds a CRC (Cyclic Redundancy Check) value to the trailer. If an error is detected at the receiver, it sends an acknowledgment requesting retransmission of the corrupted frame. Uses ARQ (Automatic Repeat Request) mechanisms.

ACCESS CONTROL

When multiple devices share the same communication channel, DLL protocols determine which device has control at a given time (CSMA/CD for Ethernet, CSMA/CA for Wi-Fi).

L3 Network Layer

Layer 3 manages device addressing and tracks the location of devices on the network. It determines the best path to move data from source to destination. Routers are Layer 3 devices.

FIG 6 · NETWORK LAYER — ROUTING BETWEEN NETWORKS

Functions

Logical Addressing (IP)
Assigns IP addresses — unique logical identifiers for every device on the network. Unlike MAC (Layer 2), IP addresses are hierarchical and routable.
Routing
Determines best path using routing protocols: RIP (hop count), OSPF (link state), BGP (between autonomous systems). Maintains routing tables.
Packet Switching
Breaks data into packets. Adds header (src IP, dst IP, TTL, protocol). Each packet is independently routed — can take different paths.
Congestion Control
Manages network traffic to prevent overload. Flow control mechanisms regulate data injection into the network.
Error Handling
Detects errors via checksums. ICMP sends error messages (e.g., "destination unreachable", TTL expired).
Fragmentation
Breaks oversized packets to fit MTU of the next link. Reassembled at the destination.

Working of Network Layer (Step-by-Step)

  1. Receive data segment from Transport Layer.
  2. Encapsulate — add IP header: Source IP, Destination IP, TTL, Protocol, Length.
  3. Route — consult routing table, forward packet to next hop router toward destination.
  4. Packet Switching — large segments broken into multiple packets, each routed independently.
  5. Deliver to Data Link Layer for frame creation and transmission.

L4 Transport Layer

The heart of the OSI model. Provides end-to-end communication between applications on different hosts. Ensures complete, error-free, sequenced data delivery. Uses port numbers to identify applications.

FIG 7 · TRANSPORT LAYER — MULTIPLEXING VIA PORT NUMBERS

Functions

End-to-End Delivery
Provides reliable connection between two applications on different hosts. Guarantees delivery in correct order.
Segmentation & Reassembly
Breaks data stream into segments with sequence numbers. Receiver reassembles in correct order.
Flow Control
Sliding Window Protocol — adjusts transmission rate based on receiver's capacity. Prevents buffer overflow.
Error Control
Detects errors via checksums. Uses ARQ (Automatic Repeat Request) to request retransmission of lost/corrupted segments.
Connection Management
TCP: 3-way handshake (SYN, SYN-ACK, ACK) to establish. 4-way (FIN) to terminate. Maintains connection state.
Multiplexing / Demultiplexing
Multiple apps share one IP connection via port numbers. Source port + Destination port in segment header identify each app.

EXAM POINT
TCP is to reliability what UDP is to speed. UDP gives up guarantees to minimize latency — critical for real-time applications like VoIP where a retransmission would arrive too late to be useful.

L5 Session Layer

Responsible for establishing, managing, and terminating communication sessions between applications on different hosts. Acts as a bridge between the application-level layers and the transport layer.

Functions

Session Establishment & Termination
Initiates and ends communication sessions. Allocates necessary resources. Sets up the dialogue control parameters.
Session Management
Determines which party can send data (half-duplex/full-duplex). Uses session identifiers to track multiple concurrent sessions.
Data Synchronization
Inserts checkpoints (synchronization points) in the data stream. If a failure occurs, transmission resumes from the last checkpoint — not from the beginning.
Multiplexing
Manages multiple sessions simultaneously over one transport connection.

Working (Step-by-Step)

  1. Session Establishment: Initiates request to remote application; negotiates transfer mode & synchronization points.
  2. Session Management: Controls data flow; uses session IDs to track; manages checkpoints.
  3. Data Synchronization: Marks end of data units with sync points; enables partial retransmission on error.
  4. Session Termination: Cleanly terminates the session; releases allocated resources.

Real-World Example — File Transfer

SCENARIO
When transferring a large file: Session layer (1) establishes the session, (2) negotiates transfer parameters, (3) places synchronization checkpoints every N MB, (4) if connection drops at 60%, resumes from the last checkpoint (not from 0%), (5) terminates session after completion.

Protocols

  • NetBIOS: Network Basic I/O System — used in older Windows LANs.
  • RPC: Remote Procedure Call — allows programs to invoke procedures on remote machines as if they were local.
  • PPTP: Point-to-Point Tunneling Protocol — creates VPN tunnels.
  • SIP: Session Initiation Protocol — sets up VoIP calls (though some models place this at Layer 7).

L6 Presentation Layer

Also called the Translator layer — it translates data between the format the application layer uses and a format suitable for network transmission. Responsible for Translation, Encryption, and Compression.

Three Core Functions

1. DATA TRANSLATION

  • Character code conversion: Different systems use different encodings. ASCII (American), EBCDIC (IBM mainframes), Unicode (universal). Presentation layer translates between them.
  • Data structure conversion: Converts complex structures into a neutral, standard format for transport (e.g., ASN.1 — Abstract Syntax Notation One).

2. DATA COMPRESSION & DECOMPRESSION

  • Reduces number of bits to transmit — critical for multimedia (text, audio, video).
  • Common algorithms: Huffman Coding, Lempel-Ziv (LZ77/LZ78), Dictionary-based compression.
  • Lossless compression (ZIP, PNG) vs. Lossy compression (JPEG, MP3).

3. DATA ENCRYPTION & DECRYPTION

  • Encrypts data at sender; decrypts at receiver — maintains privacy.
  • Common algorithms: AES (Advanced Encryption Standard — symmetric), RSA (asymmetric), DES (legacy, 56-bit — broken).
  • TLS/SSL operate here — though some models place them between L4 and L5.

Syntax & Semantics

  • Syntax: Structure/format of data (how bits are arranged).
  • Semantics: Meaning of the data.
  • Presentation layer ensures the receiver interprets the data the same way the sender intended.

Example — Image Transfer

SCENARIO
Sending a JPEG image: (1) Presentation layer converts the image format, (2) compresses it (reduces size), (3) encrypts it (if HTTPS). At the receiver — decrypts, decompresses, converts back to display format.

L7 Application Layer

The topmost layer. Serves as the window for users and application processes to access network services. Note: This layer does not mean applications like Word or Chrome — it refers to network application protocols that software uses to communicate.

Functions

FTAM — File Transfer, Access & Management
Allows users to access, retrieve, and manage files on remote computers (FTP, SFTP).
Mail Services
Provides email forwarding and storage. Uses SMTP (send), POP3/IMAP (receive).
Directory Services
Distributed database sources; global information about objects on the network (DNS, LDAP).
Network Virtual Terminal
Allows a user to log into a remote host (Telnet, SSH).
Resource Sharing
Allows sharing of hardware resources (printers, storage) across the network.
Protocol Selection
Selects appropriate protocol (HTTP, FTP, SMTP) based on data type and desired service.

Working (Step-by-Step)

  1. User Interaction: User interacts with application (browser, email client). App generates data.
  2. Data Preparation: Application layer adds necessary headers; selects protocol (HTTP, FTP, SMTP...).
  3. Data Transfer: Passes data down to Presentation layer (→ Session → Transport → Network → DLL → Physical).
  4. Data Reception: Receiving system's Application layer receives data from lower layers; extracts payload.
  5. Data Interpretation: Interprets data per protocol; presents to user in appropriate format.

KEY INSIGHT — EXAM FAVOURITE
A packet's IP addresses never change end-to-end (except with NAT). But frame MAC addresses are replaced at every hop — each router strips the incoming frame, reads the IP packet, creates a new frame with its own MAC as source and the next-hop's MAC as destination.
